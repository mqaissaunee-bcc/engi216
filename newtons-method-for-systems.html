OverviewWhat this tool is for

Almost every mechanism position problem in this course comes down to the same move: a small set of nonlinear equations that must equal zero at the same time. Newton's method is how we solve them.

In Chapter 2 your text is blunt: most mechanisms have no closed-form position solution, so we solve the loop-closure equations numerically with Newton's method. This tool lets you drive that method by hand, one step at a time, on four different systems — including a real four-bar linkage — and watch every quantity that matters: the residual, the Jacobian, its determinant, and the convergence path.

You should leave able to…

  • Write the residual vector F(x) and the Jacobian J(x) for a 2×2 nonlinear system.
  • Carry out one Newton step by hand: evaluate, solve J·Δx = −F, update.
  • Explain why convergence is normally fast (quadratic) and why it collapses to a crawl near a singular Jacobian.
  • Recognize that a four-bar's Jacobian goes singular at its toggle (dead-center) positions, and connect that to det(J)=0.
  • Implement the method in pseudocode, MATLAB, and Python, and know when to hand it to a built-in solver.

Part 1The method, the Jacobian, and convergence

Newton's method extends root-finding from one equation to a whole system. The derivative is replaced by a matrix of partial derivatives — the Jacobian.

From one equation to a system

For a single equation you know the scalar Newton step: stand on the curve, follow the tangent down to the axis, repeat. For a system of n equations in n unknowns,

F(x)= f₁(x₁,…,xₙ)f₂(x₁,…,xₙ)⋮fₙ(x₁,…,xₙ) =0

the single derivative becomes the Jacobian matrix — every function differentiated with respect to every variable. For a 2×2 system in x, y:

J= ∂f₁/∂x∂f₁/∂y∂f₂/∂x∂f₂/∂y
Analogy · A topographic map and a compass Picture each equation as a curve drawn on a contour map — the place where it equals zero. You want the one spot where both curves cross. The Jacobian is your compass: at any point it tells you which way and how far to step so that, if the curves were straight lines, you'd land exactly on the intersection. They aren't straight, so you overshoot a little — then re-read the compass and step again. Each reading gets you closer.

The algorithm, step by step

  1. Guess. Pick a starting point x⁰ — ideally near the solution (for mechanisms, the previous crank angle's answer).
  2. Evaluate the residual. Compute F(xᵤ) — how far each equation is from zero.
  3. Build the Jacobian. Compute J(xᵤ) at the current point.
  4. Solve the linear system. Solve J(xᵤ)·Δx = −F(xᵤ) for the correction Δx. (This is the matrix version of "divide by the slope.")
  5. Update. xᵤ₊₁ = xᵤ + Δx.
  6. Check. If ‖F(xᵤ₊₁)‖ < tolerance, stop. Otherwise return to step 2.
Pitfall · It is a solve, not a division Step 4 solves J·Δx = −F. In MATLAB that is the left division delta = -J\F; in Python it is np.linalg.solve(J, -F). Writing F/J or any element-wise division silently produces the wrong vector. The unknown is sandwiched as J·Δx, so it comes out by solving against J — never by dividing the other way.

Why it is usually fast — and when it isn't

Near a well-behaved solution, Newton's method roughly doubles the number of correct digits each step (quadratic convergence). That is why a four-bar across 360° of crank rotation — dozens of angles, a few iterations each — takes milliseconds.

That speed depends on the Jacobian being invertible at the solution. When det(J) → 0, the matrix can't be solved cleanly, the correction blows up or points nowhere useful, and convergence degrades from quadratic to a slow crawl — or fails. This isn't a bug in the method; it is the geometry of the problem telling you something.

Real world · The toggle position of a linkage For a four-bar, the two unknowns are the coupler and rocker angles θ₃, θ₄, and the Jacobian determinant works out to a strikingly simple form: det(J) = r₃·r₄·sin(θ₃ − θ₄). It hits zero exactly when the coupler and rocker line up (θ₃ = θ₄ or differ by 180°) — the toggle or dead-center positions, where the mechanism momentarily can't decide which way to move. The same singular Jacobian that stalls Newton's method is the physical lock-up you can feel in a folding table leg, a vise-grip clamp, or a knee at full extension. Watch det(J) in the simulation drop toward zero as you push a four-bar toward toggle.

The four-bar position equations

Closing the vector loop gives two scalar residuals (driver angle θ₂ known; θ₃, θ₄ unknown):

f₁ = r₂cosθ₂ + r₃cosθ₃ − r₄cosθ₄ − r₁ f₂ = r₂sinθ₂ + r₃sinθ₃ − r₄sinθ₄

Differentiating with respect to the unknowns (θ₃, θ₄):

J= −r₃sinθ₃+r₄sinθ₄+r₃cosθ₃−r₄cosθ₄

Take the determinant and a trig identity collapses it: det(J) = r₃r₄(sinθ₃cosθ₄ − cosθ₃sinθ₄) = r₃r₄sin(θ₃ − θ₄). That is the bridge between the linear-algebra condition and the mechanism's geometry.

Part 3Implement it: pseudocode, MATLAB, Python

The same six steps in three forms. Read the pseudocode to understand the logic, then pick the language you actually work in. You hand-code Newton to understand it; you call a built-in solver to use it.

Language-agnostic. This is the logic every implementation shares.

newton_system.pseudo
function NEWTON_SYSTEM(F, J, x0, tol, maxiter):
    # F(x) -> residual vector      J(x) -> Jacobian matrix
    # x0  -> starting guess         tol  -> convergence tolerance
    x ← x0
    for k = 1 to maxiter:
        f ← F(x)                  # 1. evaluate residual
        if norm(f) < tol:           # 6. converged?
            return x, "converged", k
        Jk ← J(x)                 # 2. build the Jacobian
        if |det(Jk)| < tiny:        #    near-singular guard
            return x, "singular Jacobian", k
        Δx ← SOLVE(Jk · Δx = −f) # 4. solve linear system (NOT divide)
        x ← x + Δx               # 5. update
    return x, "max iterations reached", maxiter
Note · The only subtle line SOLVE(J · Δx = −f) means solve a linear system, not invert and multiply. Forming J⁻¹ explicitly is slower and less accurate; every language below uses a dedicated solver instead.

Cleaned from a classroom version: the option-reader is renamed so it no longer shadows MATLAB's built-in getfield, and the Newton step uses the backslash solve.

newton_system.m
function [x, hist] = newton_system(F, J, x0, opt)
% NEWTON_SYSTEM  Solve F(x)=0 for a system using Newton's method.
%   F  : handle returning the residual column vector  f = F(x)
%   J  : handle returning the Jacobian matrix         Jk = J(x)
%   x0 : starting guess (column vector)
%   opt: struct with optional fields tol, maxiter, verbose
    if nargin < 4, opt = struct(); end
    tol     = getOpt(opt, 'tol',     1e-10);
    maxiter = getOpt(opt, 'maxiter', 50);
    verbose = getOpt(opt, 'verbose', true);

    x = x0(:);                          % force column
    hist.x = x;  hist.normF = [];

    for k = 1:maxiter
        f  = F(x);                      % 1. residual
        nf = norm(f);
        hist.normF(end+1) = nf;
        if verbose
            fprintf('iter %2d   ||F|| = %.3e\n', k-1, nf);
        end
        if nf < tol, return; end     % 6. converged

        Jk = J(x);                      % 2. Jacobian
        if abs(det(Jk)) < 1e-12        % near-singular guard
            warning('Jacobian ~singular (det=%.2e) -- toggle position?', det(Jk));
            return;
        end

        dx = -Jk \ f;                   % 4. SOLVE J*dx = -f  (left divide)
        x  = x + dx;                    % 5. update
        hist.x(:,end+1) = x;
    end
    warning('Reached maxiter (%d) without converging.', maxiter);
end

function v = getOpt(s, name, default)   % renamed -- do NOT call this getfield
    if isfield(s, name), v = s.(name); else, v = default; end
end

A direct NumPy translation — same six steps. np.linalg.solve(J, -f) is the exact analogue of MATLAB's -J\f.

newton_system.py
import numpy as np

def newton_system(F, J, x0, tol=1e-10, maxiter=50, verbose=True):
    """Solve F(x) = 0 for a system using Newton's method.

    F : callable returning the residual vector  f = F(x)
    J : callable returning the Jacobian matrix  Jk = J(x)
    x0: starting guess (1-D array)
    Returns (x, info) where info has 'status', 'iters', 'history'.
    """
    x = np.array(x0, dtype=float)
    history = [x.copy()]
    for k in range(maxiter):
        f  = np.asarray(F(x), dtype=float)      # 1. residual
        nf = np.linalg.norm(f)
        if verbose:
            print(f"iter {k:2d}   ||F|| = {nf:.3e}")
        if nf < tol:                            # 6. converged
            return x, {"status": "converged", "iters": k, "history": history}

        Jk = np.asarray(J(x), dtype=float)      # 2. Jacobian
        if abs(np.linalg.det(Jk)) < 1e-12:      # near-singular guard
            return x, {"status": "singular Jacobian (toggle?)", "iters": k, "history": history}

        dx = np.linalg.solve(Jk, -f)            # 4. SOLVE J dx = -f  (not invert!)
        x  = x + dx                             # 5. update
        history.append(x.copy())
    return x, {"status": "max iterations reached", "iters": maxiter, "history": history}

Four-bar example & SciPy's solver

run_fourbar.py
import numpy as np
from scipy.optimize import fsolve   # or: from scipy.optimize import root

r1, r2, r3, r4 = 12.0, 4.0, 13.0, 8.0
th2 = np.deg2rad(60.0)

def F(t):
    t3, t4 = t
    return np.array([
        r2*np.cos(th2) + r3*np.cos(t3) - r4*np.cos(t4) - r1,
        r2*np.sin(th2) + r3*np.sin(t3) - r4*np.sin(t4),
    ])

def J(t):
    t3, t4 = t
    return np.array([
        [-r3*np.sin(t3),  r4*np.sin(t4)],
        [ r3*np.cos(t3), -r4*np.cos(t4)],
    ])

t0 = np.deg2rad([10.0, 70.0])               # open-config guess
t, info = newton_system(F, J, t0)
print(f"theta3 = {np.rad2deg(t[0]):.3f} deg,  theta4 = {np.rad2deg(t[1]):.3f} deg")
print(info["status"], "in", info["iters"], "iterations")

# Same problem with SciPy (give it the analytic Jacobian for speed/accuracy):
t_scipy = fsolve(F, t0, fprime=J)
Note · No analytic Jacobian? Approximate it. If the partial derivatives are painful to derive, replace J(x) with a finite-difference estimate: perturb each variable by a small h, recompute F, and divide. SciPy's fsolve and root do this automatically when you omit fprime — convenient, but a hand-derived Jacobian is faster and more accurate.

From these examples to the rest of the course

Once you can form the Jacobian, you've unlocked most of Chapters 2 and 4. Position analysis (nonlinear) needs Newton, which builds J. Velocity and acceleration analysis are linear once position is known — and they reuse that same Jacobian, just changing the right-hand side. One matrix, three jobs.
